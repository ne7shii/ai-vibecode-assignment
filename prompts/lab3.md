1. System Architecture: เครื่องผู้ใช้ (เบราว์เซอร์ + Playwright) → web: Next.js (App Router, TypeScript) มีหน้าเว็บ + API + กฎโรงแรม

2. Use Case (Mermaid ไม่มีชนิดนี้ ให้ใช้ flowchart LR: actor เป็นวงรี ระบบเป็น subgraph แยก "หน้าเว็บ" กับ "หลังบ้าน"): actor = ชื่อบทบาท + ชื่อคนในวงเล็บ ครบทุกกลุ่มในบันทึกสัมภาษณ์ + ทีมงานทั้ง 4 คน · ทุก use case โยงรหัส FR

Flowchart อย่างน้อย 4 รูป: ค้นหาห้องว่าง (ตรวจช่วงวัน → จำนวนคนและเด็ก → ว่างทุกคืน → แผนราคา) · จองและจ่ายเงิน (ล็อก 15 นาที → จ่าย → สำเร็จ / ไม่สำเร็จ / หมดเวลา) · ยกเลิกและเปลี่ยนวัน (เวลายกเลิกฟรีตามซีซั่น · Non-refundable) · คำนวณราคาสุทธิตามลำดับของโรงแรม (รายคืน → โปรราคา → Non-refundable → สมาชิก → โค้ด → ของเสริม → ปัดเศษ → มัดจำ) · ทุกจุดตัดสินใจเขียนรหัส BR กำกับ
4. ERD: ตาราง คอลัมน์หลัก และความสัมพันธ์ · คอลัมน์เงินและแต้มต้องระบุชนิดข้อมูล (เงินใช้ NUMERIC ไม่ใช้ float) · การจองต้องเก็บ "ราคาที่ล็อกไว้ตอนจ่าย" แยกจากราคาปัจจุบัน
