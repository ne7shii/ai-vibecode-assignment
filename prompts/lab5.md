# LAB 5 · พรอมต์สร้างเว็บ

📋 เปิด Claude Code เซสชันใหม่ที่โฟลเดอร์ `sabaijang/` แล้ววางกล่องนี้

```text
อ่าน REQUIREMENTS.md, DESIGN.md, TEST-DATA.md, ดูรายชื่อรูปใน brand-kit/ และอ่าน brand-kit/CREDITS.md (ขั้นนี้ห้ามเขียนโค้ดเว็บ)
แล้วเขียนไฟล์ BUILD-PROMPT.md = พรอมต์ภาษาไทยที่ผมจะ copy ไปวางให้ Claude หน้าต่างใหม่สร้างเว็บ "CWN สบายจัง รีสอร์ท · CWN Sabai Jang Resort" ใหม่ทั้งหมด
พรอมต์นั้นต้องสั่งให้ครบทุกข้อนี้
1. ทำตาม DESIGN.md: Next.js (App Router, TypeScript) ต่อ PostgreSQL 16 ด้วยไลบรารี pg เขียน SQL ตรง ๆ (ไม่ใช้ ORM)
2. Docker แยก 2 โปรเจกต์ คุยกันผ่าน network ชื่อ hotel-net
   - db/ : container hotel-db (postgres:16-alpine) · volume hotel-pgdata · พอร์ต 5434:5432 · healthcheck pg_isready
           db/init/01-schema.sql ตาม ERD (ข้อมูลใน TEST-DATA ที่ ERD ยังไม่มีตาราง ให้เพิ่มตารางได้) · db/init/02-seed.sql ตาม TEST-DATA.md ทุกค่า
   - web/: container hotel-web พอร์ต 3100 (ใน container ใช้ 3000 ได้ map 3100:3000) · DATABASE_URL ชี้ไปที่ hotel-db:5432 · output standalone · HOSTNAME=0.0.0.0 · TZ=Asia/Bangkok
           healthcheck ด้วย node เรียก /api/health ตอบ {"ok":true,"db":true} (ต่อฐานข้อมูลไม่ได้ให้ตอบ db:false) · ห้ามต่อฐานข้อมูลตอน build
   - เปิด db ก่อน รอ healthy แล้วค่อยเปิด web · ห้ามแตะ container ของเว็บสปา (sabai-web, sabai-db) ที่อาจเปิดอยู่
3. ใช้ได้บน Windows และ macOS: ไม่มีไฟล์ .sh ที่ต้องรัน · .gitattributes ให้เป็น LF
   ถ้ามี container อื่นใช้พอร์ต 3100 หรือ 5434 อยู่ ให้บอกชื่อแล้ว docker stop ก่อน
4. รูปในเว็บ: ใช้รูปจาก brand-kit/ ทั้งหมด (คัดลอกไป web/public/brand/ ด้วยชื่อเดิม แล้วใช้ next/image หรือ srcset ให้โหลดเร็ว) ห้ามใช้รูปจากเน็ตเพิ่ม ห้ามใช้ภาพการ์ตูนหรือไอคอนแทนรูปคน
   ห้องแต่ละประเภทใช้รูปของห้องนั้นตามชื่อไฟล์ (rooms/r01-* ถึง r06-*) · ทีมงานและผู้เข้าพักในรีวิวใช้รูปใน people/ · ทัวร์ 360° ใช้ pano/ (หมุนในเบราว์เซอร์ด้วยไลบรารีจาก npm ไม่โหลดจาก CDN)
   รูปใน brand-kit มาจากคลังภาพฟรี บางรูปเป็น CC BY ที่ต้องให้เครดิต: ทำหน้า /credits จาก brand-kit/CREDITS.md (รูป | เจ้าของ | สัญญาอนุญาต | ลิงก์ต้นฉบับ) และลิงก์ "เครดิตรูปภาพ" ที่ footer ทุกหน้า
   เขียน web/ASSETS.md: ไฟล์ | ใช้ที่หน้าไหน | ที่มา
5. ดีไซน์ต้อง "ว้าว" ระดับเว็บรีสอร์ตหรูริมทะเลอันดามัน (ฟ้าทะเลอันดามัน ทรายขาว ไม้สัก เขียวใบมะพร้าว ทองอ่อน)
   - หน้าแรก: hero เต็มจอเปลี่ยนภาพ 3 ภาพ (hero-beach, hero-pool, hero-sunset) แบบ crossfade + ซูมช้า ๆ พาดหัวฟอนต์เซอริฟตัวใหญ่ · กล่องค้นหาห้องลอยบน hero (วันที่ ผู้ใหญ่ เด็ก) · เลื่อนแล้วเนื้อหาค่อย ๆ ปรากฏ · parallax
     · การ์ดห้องรูปใหญ่ hover แล้วเห็นราคาเริ่มต้น · แถบโปรโมชั่น · สิ่งอำนวยความสะดวก · แผนที่และระยะทาง · รีวิวพร้อมรูปและคะแนน · ทีมงานต้อนรับ
   - header โปร่งใสบน hero แล้วทึบเมื่อเลื่อน · ปุ่ม "จองห้อง" ลอยบนมือถือ · แถบสรุปราคาติดล่างจอทุกขั้นตอนการจอง · การ์ดมีเงานุ่ม เส้นทองบาง · transition นุ่มทุกหน้า · ฟอนต์ผ่าน @fontsource (ไม่พึ่งอินเทอร์เน็ตตอนรัน)
   - ใช้ได้สวยบนมือถือ 375px ไม่เลื่อนข้าง · เคารพ prefers-reduced-motion · หน้าแรกโหลดไม่เกิน 3 วินาที
6. ฟีเจอร์ครบตาม REQUIREMENTS.md ทุก FR (ทั้ง 56 story) · ตัวเลขทุกตัวตรงตาม BR และ TEST-DATA.md · ภาษาไทยและอังกฤษทุกหน้า รวมอีเมล
   หลังบ้าน /admin เข้าได้ตามสิทธิ์ 4 บทบาทใน TEST-DATA: ซีซั่น ราคาเฉพาะวัน โปรโมชั่นและโค้ด Flash Sale · ห้องและปิดห้องซ่อม · รายการแขก เช็กอิน เช็กเอาต์ No-show ยืนยันบริการเสริม · รายงาน + ดาวน์โหลด Excel · ตอบรีวิว
7. บริการภายนอกจำลองทั้งหมด ไม่เรียก API ภายนอก
   - หน้าจ่ายเงินจำลองตามบัตรทดสอบใน TEST-DATA (สำเร็จ / ถูกปฏิเสธ) และ PromptPay QR จำลอง · เว็บไม่เก็บเลขบัตร
   - อีเมลและ LINE แจ้งโรงแรม: บันทึกลงตาราง outbox แล้วแสดงที่ /admin/outbox (หัวเรื่อง เนื้อหา ผู้รับ เวลา ภาษา)
   - แชตบอตเป็นกฎตายตัว ถามเหมือนเดิมตอบเหมือนเดิม · อัตราแลกเปลี่ยนใช้ค่าคงที่ใน TEST-DATA · แผนที่ใช้ภาพนิ่งหรือ iframe ที่ไม่บังคับต้องมีเน็ตตอนทดสอบ
8. สำหรับทดสอบ: data-testid ทุกปุ่ม ช่องกรอก ผลลัพธ์ ราคาทุกบรรทัด และข้อความ error · <html data-ready="true" data-bug-mode="0|1">
   POST /api/test/reset (เปิดเมื่อ ALLOW_TEST_RESET=1) ล้างข้อมูลกลับเป็น seed และรับ {"now":"<วันเวลา ISO>"} เพื่อล็อก "วันนี้" ของเว็บ (ไม่ส่ง now = ใช้วันล็อกใน TEST-DATA.md)
   POST /api/test/clock (เปิดเมื่อ ALLOW_TEST_RESET=1) รับ {"now":...} หรือ {"advanceMinutes":N} เลื่อนนาฬิกาโดยไม่ล้างข้อมูล (ไว้ทดสอบล็อก 15 นาที Flash Sale หมดเวลา เวลายกเลิกฟรี No-show)
9. BUG_MODE (env ของ web ค่าเริ่มต้น 0): ให้ Claude เลือกบั๊กเอง 3 ตัวจาก BR ใน REQUIREMENTS.md
   1 ตัวเรื่องเงิน · 1 ตัวเรื่องการจองหรือห้องว่าง · 1 ตัวเรื่องตัวเลขหรือสถานะที่ต้องอัปเดตหลังทำรายการ
   ทุกตัวต้องเป็นแบบที่ "ถ้าลอกค่าจากหน้าจอไปเป็นผลที่คาดหวัง จะจับไม่ได้"
   เขียนเฉลยไว้ที่ web/BUGS.md เท่านั้น ห้ามบอกในแชท ห้ามเขียนใน SPEC.md หรือคอมเมนต์ที่เดาง่าย
10. เขียน web/SPEC.md: หน้าเว็บ · กฎโยงรหัส FR/BR · data-testid ทุกตัว · ข้อความ error คำต่อคำทั้ง 2 ภาษา · API ทุกเส้น · ผู้ใช้ seed · บัตรทดสอบ
11. ขั้นสุดท้าย: เปิด db แล้ว web รอจน 2 container healthy · ตรวจ /api/health · ยิง API ตรวจกฎโรงแรมตามตารางค่าขอบใน TEST-DATA.md แล้วรายงาน "ผ่าน X / Y ข้อ"
    · ถ่ายภาพหน้าแรกและหน้าห้องพักจอคอมและมือถือด้วย playwright-cli แล้วดูเองว่าสวยและรูปขึ้นครบ ถ้าไม่สวยให้แก้ก่อน · เปิด http://localhost:3100 ให้ผมดู · สรุปเป็นตาราง (ห้ามบอกว่าเลือกบั๊กอะไร) · ถ้าขั้นไหนไม่ผ่านให้หยุดแล้วบอกสาเหตุ
12. สร้างแบบ multi-agent เพื่อให้เร็ว ไม่ทำทีละฟีเจอร์ แบ่ง 3 ช่วง และเขียนลำดับนี้ไว้ในพรอมต์
    ช่วง A หัวหน้าทำคนเดียว (= สัญญากลางที่ทุกคนยึด): โครงโปรเจกต์ · db/ ทั้งชุด · type กลาง · lib ต่อฐานข้อมูล · ระบบ i18n + นาฬิการะบบ + testid · lib คิดราคากลาง (ลายเซ็นฟังก์ชันและ type ผลลัพธ์รายบรรทัด) · design system และ layout กลาง (สี ฟอนต์ ปุ่ม การ์ด header footer แถบราคา)
          · web/API-CONTRACT.md: API ทุกเส้น (method · path · body · response · error code) · ตาราง "ใครเป็นเจ้าของไฟล์ไหน"
    ช่วง B สั่ง subagent ทุกตัวในข้อความเดียว (ไม่ใช้โหมดเบื้องหลัง) รอจนครบ · หน้าเว็บกับ API ทำพร้อมกันได้เพราะยึด API-CONTRACT.md · แต่ละตัวแก้ได้เฉพาะไฟล์ของตัวเอง ห้ามแก้ไฟล์กลาง ถ้าสัญญาขาดให้จดใน web/CONTRACT-NOTES/<ชื่อ>.md · ห้ามรัน docker · ห้ามทำ BUG_MODE
       ฝั่ง API 6 ตัว: A1 ห้องว่าง นับห้องรายคืน ล็อก 15 นาที ปิดห้องซ่อม · A2 คิดราคา ซีซั่น ราคาเฉพาะวัน โปร ซ้อนส่วนลด โค้ด มัดจำ แต้ม (lib กลางตัวเดียว + unit test ค่าขอบจาก TEST-DATA) · A3 จอง จ่ายเงินจำลอง outbox ยกเลิก เปลี่ยนวัน จัดการด้วยรหัสการจอง (จำกัดผิด 5 ครั้ง)
                 · A4 สมัคร เข้าสู่ระบบ ยืนยันอีเมล บัญชี แต้ม เดือนเกิด ประวัติ ลบบัญชี · A5 หลังบ้าน: ซีซั่น โปร Flash Sale ห้อง รายการแขก เช็กอิน/เอาต์ No-show รายงาน Excel สิทธิ์ 4 บทบาท · A6 รีวิว ข้อมูลโรงแรม แชตบอต สกุลเงิน reset clock
       ฝั่งหน้าเว็บ 8 ตัว: F1 หน้าแรกแบบว้าว ข้อมูลโรงแรม แผนที่ นโยบาย · F2 ห้องพัก รายละเอียด แกลเลอรีเต็มจอ 360° เปรียบเทียบห้อง · F3 ค้นหา ปฏิทินราคา ผลค้นหา แผนราคา · F4 จอง 4 ขั้น หลายห้อง สรุปราคารายคืน จ่ายเงินจำลอง นับถอยหลัง หน้าสำเร็จ
                 · F5 สมัคร login บัญชี แต้ม ประวัติ จัดการการจอง ยกเลิก เปลี่ยนวัน · F6 หน้ารวมโปร แพ็กเกจ Flash Sale นับถอยหลัง · F7 หลังบ้านทุกเมนู + outbox · F8 รีวิว แชตบอต สลับภาษา สกุลเงิน PDPA ความยินยอม /credits
       ทุกตัวเขียนข้อความ 2 ภาษาในไฟล์ i18n ของตัวเอง
    ช่วง C หัวหน้า: อ่าน CONTRACT-NOTES แก้จุดต่อ · ทำ BUG_MODE และ web/BUGS.md (เฉพาะหัวหน้ารู้) · เขียน SPEC.md และ ASSETS.md · build แล้วเปิดเว็บ
       จากนั้นสั่ง subagent ตรวจ 2 ตัวพร้อมกันบนโหมดปกติ: V1 เปิดทุกหน้าจอคอมและมือถือด้วย playwright-cli แล้วแก้ดีไซน์ที่ไม่สวยหรือรูปไม่ขึ้น · V2 ยิง API ตามตารางค่าขอบแล้วแก้กฎที่ผิด · แล้วหัวหน้าทำขั้นสุดท้ายในข้อ 11
ให้ BUILD-PROMPT.md สั้นที่สุดเท่าที่ยังครบ (ไม่เกิน 190 บรรทัด) แบ่งเป็นขั้นมีเลขกำกับ
เสร็จแล้วสรุปเป็นตาราง: ขั้นในพรอมต์ | FR/BR ที่ครอบคลุม
```
